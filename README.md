# PULSE conjoint survey

The Option C review release adds a separate `/v3/` instrument and test collection endpoint. See the [v3 release and routing guide](docs/V3_RELEASE.md) for deployment and verification.

Version 2 implements the A0.8-derived A0.9 questionnaire test: routed travel/COM-B, one WPT or V2G acceptance module and technology DCE, a public/non-user path, four benefit priorities and isolated instrument-test collection.

The earlier online v1 is preserved at /v1/. After deployment the root opens /v2/. Source publication in GitHub does not by itself update the Cloudflare Worker: use the already configured local Cloudflare project below.

## Publish to the existing survey Worker

Clone this repository into a directory separate from the configured deployment project. Run a dry-run with the existing separate survey database UUID:

```bash
node scripts/install-v2.mjs /path/to/configured/pulse-conjoint-survey --database-id EXISTING_SURVEY_D1_UUID --collect-tests
```

Then apply and publish:

```bash
node scripts/install-v2.mjs /path/to/configured/pulse-conjoint-survey --database-id EXISTING_SURVEY_D1_UUID --collect-tests --apply --deploy
```

The guard verifies Worker/database identity and EU jurisdiction, backs up files, preserves the original backend and runtime settings, adds only the isolated test table/API, publishes, and verifies one labelled test record through the live API and D1. Other Workers and the original application's database remain outside the operation. See [release details](docs/V2_RELEASE.md).

## Development and checks

Use Node 22.13+; there are no npm dependencies. SQLite is used only by local tests/development, while production uses D1.

```bash
npm run check
npm run dev
python3 -m unittest discover -s tests -p 'test_analysis.py'
```

Local development uses in-memory test storage and the official Cloudflare dummy verification keys. It never connects to the live D1 database. The site preview service may be required in managed environments.

## Instrument and analysis

[Instrument JSON](public/v2/survey.json), [Excel-readable codebook CSV](instruments/v2-codebook.csv) and [source manifest](instruments/v2-manifest.json) preserve IDs, candidate construct roles, source task IDs and content versions. Candidate means are not validated scales; W09/V09 are clarity prototypes, not final fieldwork designs.

[Python preparation and MATLAB scaffold](docs/DATA_CONTRACT.md) export route-specific features and alternative-level choices. Instrument tests and synthetic data are distinct from study responses. Synthetic population generation and behavioural-twin archetype validation follow flow review; no population is generated by this release.
